# Troubleshooting

| Symptom | Fix |
|---|---|
| Anything unclear about the machine | `nomarmy doctor`, then `nomarmy health` |
| A worker's commands come back `Aborted`, even simple reads, or jobs fail in ways that make no sense (macOS, Windows) | macOS: the Podman VM is too small: every sandbox, verification run and image build shares its memory, and Podman's default is 2 GiB. `nomarmy sandbox` shows it; `nomarmy sandbox --memory 8` resizes it (doctor fails below 4 GiB). Windows: Podman runs inside WSL and shares WSL2's memory (about half the machine by default); raise `memory=` under `[wsl2]` in `%UserProfile%\.wslconfig`, then `wsl --shutdown` |
| Every sandbox fails to start with `error during chown ... permission denied` or `insufficient UIDs or GIDs available in user namespace`, often right after the Podman VM restarted | Rootless Podman lost its subordinate ID ranges (`/etc/subuid`, `/etc/subgid` emptied). `nomarmy doctor` detects it; `nomarmy sandbox --repair` restores them (it waits until no job is running, since it restarts Podman's containers) |
| The disk fills up with old images | `nomarmy sandbox --prune` removes images no container uses; nomArmy rebuilds its own when a job needs them |
| `No API key found for provider "llama-cpp"` during `e2e.sh` | `./scripts/configure-openclaw.sh <profile>`, then rerun |
| Jobs on an api agent fail with `No API key found` | OpenClaw never saved its key, usually because `agents.yml` was written by hand. Export the agent's `auth_env` variable, then `nomarmy agents register <name>` |
| A job fails with, or is refused for, `model_not_found` | Your plan or OpenClaw can't run that model (nomArmy tests an unproven model before its first job). `nomarmy agents list` shows which roles use it; `nomarmy army assign <role> <agent> <model>` moves the role and tests the new model |
| Verification fails on a missing package | Node: commit your lockfile (npm, pnpm, yarn and bun lockfiles and workspaces are installed). Python: list your requirements files under `environment.python.requirements`, or commit `uv.lock`, `poetry.lock` or a `pyproject.toml` |
| A job sits with no progress, or times out with no report, right after a lockfile changed | The sandbox image is rebuilding. A build stops after 30 minutes (`NOMARMY_IMAGE_BUILD_TIMEOUT_MINUTES`) and Playwright's browser install after 5 minutes per attempt. beta.4 and earlier hung for good on Playwright before 1.60, whose browser extraction never finishes on Node 26; nomArmy now works around it. If the repo matches the browser harness but its end-to-end tests run elsewhere, add `exclude_harnesses: [browser-playwright]` to `.nomarmy.yml` |
| Every sandbox fails with `SandboxProvisioningError ... container.env: no such file or directory` (Linux) | The service running nomArmy or OpenClaw has systemd `PrivateTmp=yes`. OpenClaw writes sandbox files under `/tmp/openclaw` and ignores `TMPDIR`, so Podman can't see them. Set `PrivateTmp=no` in that unit and restart it; `nomarmy doctor` lists such units |
| Verification fails with `EACCES` writing inside the checkout (Linux) | Rootless Podman older than 4.3 can't map your user into the sandbox. Upgrade Podman |
| A config change didn't take effect | `nomarmy stop <profile> && nomarmy start <profile>` for local inference (hosted setups have none); restart your coordinator after `nomarmy connect` or an update |
| `git worktree add` fails with `Filename too long` (Git for Windows) | `git config --global core.longpaths true`. Job worktrees on Windows are made by Git inside WSL, which has no such limit |
| Not sure a setting fits your hardware | `nomarmy sizing`, or `nomarmy sizing --check` |
