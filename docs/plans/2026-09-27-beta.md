# Plan: beta, and the Claude and Codex marketplaces

**Status: step 1 in review (PR #94); marketplace research done.** Beta means stable enough to depend on: a feature freeze, then fixes only until every box below is ticked, then `0.1.0-beta.1` and the marketplace listings together.

## Why now, and why not yet

nomArmy has what it set out to do: jobs on local models, api keys and subscriptions; a verified record for every job; the revert check; harnesses; the network ladder; validators; stats. A real `/feature` run on Senti passed a hidden 33-check grader on its first try.

But the last few days of real use found a serious bug nearly every day: harnesses never reached connected sessions (alpha.6 to alpha.8), a worker could rewrite a check to pass, guarded commands that ran nothing read as passed, the idle breaker cut off working jobs. Each was fixed within hours, and each was in a release someone was running. A marketplace listing brings people who won't file an issue, so the core has to settle first.

## 1. The last features

- [x] **`stakes: high` on a job** (PR #94). Security, data loss and irreversible changes need more than a harder model: they make a verification profile, the judge and an independent review mandatory, and flag acceptance without one. Most defects that passed every check on Senti were this kind (cross-tenant access, a false security label, deploy-only paths).
- [x] **Routing suggestions** (PR #94). `nomarmy stats`, the `army` tool and health warnings suggest routing changes from the job records (a role that fails often, a cheaper model doing as well, a costly reviewer), each with its evidence and the command to apply it. Never applied automatically; minimum sample sizes.

Then **feature freeze**: fixes only until beta.

## 2. The beta checklist

- [ ] **A quiet stretch:** about a week of real use with no serious bug. The clock starts after step 1 ships.
- [ ] **Fresh-machine installs**, end to end from `npm install -g nomarmy@alpha` to a first `/feature` run: a clean macOS and a clean Linux machine. The pinned-OpenClaw install path (alpha.7) has never run from scratch.
- [ ] **Security review** (the security-analyst role, as for registries and the allowlist) of everything added since the last one: Jev key storage, the judge's host-tool consent, `continue_from`, per-repo registration and `nomarmy mcp`, `local_worker_stop`, mutation testing's file restores, `stakes: high`.
- [ ] **Two or three outside users** besides Senti, with their friction fixed.
- [ ] **Config compatibility:** from beta on, changes to `agents.yml`, `validators.yml`, `.nomarmy.yml` and `config.yml` come with a migration or a clear error naming the fix, never silent breakage. Write the promise into CONTRIBUTING.
- [ ] **Docs pass:** a new user can go from the README to a working `/feature` without asking anyone.

## 3. Marketplaces (in parallel with step 2)

Packaging, not features, so it can proceed during the freeze. Every listing states plainly that it needs `npm install -g nomarmy` and `nomarmy setup` first: a listing can register nomArmy, but it can't install Podman, OpenClaw or your agents.

- [x] **Research** each platform's current requirements (below).
- [ ] **One plugin, three marketplaces, in this repository:** `.claude-plugin/` (Claude Code), `.agents/plugins/marketplace.json` (Codex) and `.cursor-plugin/` (Cursor), each registering `nomarmy mcp` and shipping `/feature`, plus a start-of-session check that tells the user to run `npm install -g nomarmy` and `nomarmy setup` when `nomarmy` isn't on PATH.
- [ ] **No double registration:** a plugin registers the MCP server itself, so `nomarmy setup` and `nomarmy connect` must notice the plugin and not add a second `nomarmy-local-worker`.
- [ ] **Official directories:** Claude's (claude.ai/directory/manage), Cursor's (cursor.com/marketplace/publish), and the MCP Registry (which feeds GitHub's registry and VS Code).
- [ ] **Codex's public directory** doesn't accept a local stdio server, so it's either a skills-only listing pointing at the self-hosted marketplace, or asking OpenAI about local MCP support.
- [ ] **Release `0.1.0-beta.1`** and publish the listings the same day.

### Marketplace research (2026-09-27)

From each platform's current documentation.

**Claude Code** ([plugins](https://code.claude.com/docs/en/plugins/manifest-reference.md), [marketplaces](https://code.claude.com/docs/en/plugins/create-marketplace.md), [publishing](https://code.claude.com/docs/en/plugins/publish.md))
- A plugin: `.claude-plugin/plugin.json` (only `name` required), `commands/`, `agents/`, `skills/`, `hooks/hooks.json`, and MCP servers in `.mcp.json` or `mcpServers`. A `command`/`args` server such as `nomarmy mcp` is allowed; `${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_PROJECT_DIR}` resolve.
- A GitHub repo can be the marketplace (`.claude-plugin/marketplace.json`): `/plugin marketplace add rayson-tech/nomarmy`, then `/plugin install nomarmy@<marketplace>`. The marketplace entry's `name` must match `plugin.json`'s.
- Official directory: submit at claude.ai/directory/manage (needs a paid plan), reviewed by Anthropic, then synced to Claude Code, claude.ai and Cowork. Review criteria aren't published.
- No standard way to declare prerequisites: a `SessionStart` hook can check for `nomarmy` and warn; a failed MCP start shows in `/plugin`'s Errors tab.
- Versioning: bump `version` in `plugin.json`; auto-update is off by default.

**Codex** ([plugins](https://developers.openai.com/plugins/build/plugins), [submission](https://developers.openai.com/plugins/deploy/submission))
- Plugins carry skills, MCP servers and hooks in the portable Agent Plugins format: `plugin.json` at the root (`$schema`, `name`, `version`, `description`), `mcp.json`, `skills/<name>/SKILL.md`. The older `.codex-plugin/plugin.json` still works.
- Self-hosted marketplace: `.agents/plugins/marketplace.json` in a repo; `codex plugin marketplace add owner/repo`. Works in the CLI and the desktop app.
- Public directory (platform.openai.com/plugins) needs a verified identity and test cases, and **doesn't accept local stdio MCP servers**: remote MCP, skills, or both.

**Cursor** ([plugins](https://cursor.com/docs/plugins), [reference](https://cursor.com/docs/reference/plugins), [install links](https://cursor.com/docs/context/mcp/install-links))
- `.cursor-plugin/plugin.json` (only `name` required), a root `mcp.json` with stdio servers, `${CURSOR_PLUGIN_ROOT}`.
- Marketplace: submit at cursor.com/marketplace/publish. Plugins must be open source, every update is reviewed, and the README must cover setup.
- One-click install link: `cursor://anysphere.cursor-deeplink/mcp/install?name=<name>&config=<base64 JSON>`.

**MCP Registry** ([package types](https://modelcontextprotocol.io/registry/package-types), [authentication](https://modelcontextprotocol.io/registry/authentication), [quickstart](https://modelcontextprotocol.io/registry/quickstart))
- In preview. `server.json` lists the npm package (`registryType: npm`, stdio); `package.json` needs a matching `mcpName`. GitHub login grants `io.github.rayson-tech/*`. Published with `mcp-publisher`.
- Feeds aggregators, including GitHub's MCP Registry and VS Code's one-click install. Still to confirm: how a client is told to run `nomarmy mcp` rather than the bare binary (the schema's argument fields).

## After beta

1.0 when beta has run without a serious bug long enough that the config promise has been kept through real changes, and the marketplace users' reports have been worked through.
